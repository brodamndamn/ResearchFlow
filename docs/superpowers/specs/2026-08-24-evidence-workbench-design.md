# ResearchFlow 证据研究台设计规范

## 目标

把 ResearchFlow 从通用 AI 仪表盘重塑为面向 HR 演示的“证据研究台”：首页表达研究入口，工作台表达研究过程，报告页表达可信结果。只调整前端结构与样式，不修改 API、路由、后端状态或数据模型。

## 视觉语言

- 夜间模式：深墨蓝 `#07141d`、研究面板 `#0d222c`、薄荷绿 `#4fd1be`、证据蓝 `#7c9eff`、暖黄 `#e0a85b`。
- 日间模式：雾白 `#f1f6f4`、纸面白 `#fcfefd`、研究绿 `#147d72`、证据蓝 `#4169a8`、风险黄 `#a96d19`。
- 标题使用本地宋体栈，正文使用中文无衬线字体，编号、任务 ID 和指标使用等宽字体。
- 减少等权圆角卡片、强烈发光与无意义装饰；用层级、细线、标签和留白组织信息。

## 标志性元素

全站复用“证据路径”：`问题 → 计划 → 搜索 → 证据 → 报告`。首页展示产品方法，工作台展示当前阶段，报告页展示完整闭环。路径节点必须有文本含义、当前状态和可访问语义，不作为纯装饰。

## 页面结构

### 首页

桌面端采用左右研究台：左侧为产品命题、说明与证据路径，右侧为研究输入控制台；移动端单列。精选案例采用一个主案例和两个次案例的层级，最近研究采用紧凑档案列表。

### 工作台

顶部展示研究主题和状态，证据路径紧随其后。左侧研究时间线是过程索引，右侧计划审核或执行状态是主要工作区域。终态提示保留原有功能。

### 报告页

顶部作为报告封面，展示完成状态、题目、指标和复制链接；证据路径标记闭环完成。正文保持适合长时间阅读的行宽，目录和来源采用研究档案式结构。

## 交互与适配

- 动效仅用于证据路径进入、当前节点呼吸和必要的 hover 反馈。
- 支持 `prefers-reduced-motion`，键盘焦点必须可见。
- 在 800px 和 520px 断点保持现有移动端能力。
- 不引入外部字体、图片 CDN 或新运行时依赖。

## React 约束

- 证据阶段数据在模块级静态定义，不在页面渲染中重复创建组件类型。
- 共享的证据路径组件保持纯展示，通过原始字符串 props 接收当前阶段。
- 保留现有数据请求、状态和事件处理逻辑，不为视觉改版增加派生 state。
- 长报告来源与案例区域使用 `content-visibility` 降低离屏渲染成本。
